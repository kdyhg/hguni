# 운영 안내

## 일상 명령

| 명령 | 용도 |
|---|---|
| `서버시작.cmd` | 웹·중계·Sheets worker 시작 |
| `서버상태.cmd` | PID, HTTP health, SQLite 경로 확인 |
| `데이터백업.cmd` | `backups/`에 일관된 DB 백업 생성, 최근 30개 유지 |
| `서버종료.cmd` | 모든 로컬 프로세스 종료 |

매일 시작 전 설정 화면의 준비 상태 5개, 최근 카탈로그, 담당교사, 중계 heartbeat를 확인한다. 학생회 PIN은 교사가 당일 직접 입력한다.
자동 작업을 등록한 서버는 매일 16:30 백업하며, 수동 백업도 언제든 실행할 수 있다.

## 장애 대응

| 상황 | 조치 |
|---|---|
| 태블릿에서 접속 안 됨 | 서버상태 → Windows 네트워크가 Private인지 → 고정 IP/방화벽 확인 |
| 웹 서버 오류 | `logs/web-error.log` 확인 후 서버 재시작 |
| 중계 끊김 | `logs/bridge-error.log`, SQL 연결, source scope 확인 |
| Google Sheets 지연 | 운영은 계속 진행. `logs/sheets-error.log`와 서비스 계정 공유 권한 확인 |
| `확인 필요` | `HguniReceipt`를 먼저 조회하고 새 요청 ID로 재입력하지 않음 |
| 자동 취소 불가 | 원본에서 교사가 직접 처리하고 감사 기록 유지 |
| DB 손상 경고 | 신규 입력 중지, 서버 종료, 최신 `backups/*.db`를 별도 위치에서 검증 후 복구 |

Google Sheets의 행을 수정해도 SQLite나 유니쿨 원본은 바뀌지 않는다. Sheets는 보고용 단방향 복제본이다.

학생 snapshot·감사 기록의 보관기간은 학교 개인정보 방침에 맞춰 별도 결정한다. 백업은 서버 PC와 다른 물리 장치 또는 접근 제한된 교내 공유 폴더에도 정기 복제한다.
